01 — the flow

Prompt in, one file out

Everything below the intent parser is built and works end to end. The parser itself is not, so today the parameters are typed on a command line.

Planner — picks the tracks and their order

Pool is genre plus BPM range, optionally with an energy floor. Then a beam search of width 8 walks the set forward, scoring each candidate on four things and vetoing on hard rules: BPM within 5%, Camelot distance ≤ 2, one track per artist, none repeated.

Fetcher — turns names into audio it can trust

Searches YouTube, then applies two gates. Duration must be 4 to 15 minutes, checked on the decoded file and not just the metadata. Then a constellation fingerprint has to find the track's own 30-second preview inside the download. Real pairs score 457 to 14,466 matching hashes; wrong recordings score 21 or fewer.

Mixer — renders the audio

Segments each track, picks which window of it to play, stretches everything to one tempo, then makes four independent decisions at every seam.

03 — status

Where it stands

Catalog and modelsdone

2,834 mixes, 28,460 tracks with embeddings and features. Model A (0.663 AUC), Model B (+17% MRR), GBM edge scorer (0.69 AUC).

Plannerdone

Beam search with hard rules, energy curves, an energy floor and an optional compatibility weight.

Fetcherdone

Duration and fingerprint gates, automatic replan around anything unfetchable.

Mixerdone

Stereo, LUFS-matched, zero-phase EQ, real swept filters, per-seam beat correction, lead-and-support blending.

DJ profilespartial

mix_profiler.py exists; dj_profiler.py and dj_profiles.json do not. 48 DJs have 5+ mixes each, so the data is there. Worth roughly double what genre gives for play length.

Duration controlpartial

You get within about 10% of a requested length. Total time is not a parameter; windows flex to land on section boundaries.

Intent parsermissing

Phase 10. No natural language input at all today, and no API service. Everything is command-line arguments.

Transition criticmissing

Model C, plus the mix-audio corpus and learned cue points. There is no learned judgement of whether a rendered transition is good.

Known weak points

  • The beam deduplicates on the unordered set, so two orderings of the same tracks collide and only one survives. Ordering is never actually compared.
  • The opening track is chosen by energy distance alone, with no model involved.
  • The three beam weights were set by hand and have never been tuned.
  • A failed fetch replans the whole set rather than replacing the one slot, which can discard a well-matched plan.
  • No way to ask for a named artist, an era, or a mood outside the five energy curves.
04 — live demo

Prefetching to S3

Yes, and you should — but it solves the reliability problem, not the speed one. The bucket ai-dj-data already exists in eu-north-1.

Fetching is the fragile stage. Building the last 15-minute mix took about six minutes of fetching, including three candidates rejected by the fingerprint and one full replan. Separately, yt-dlp went stale and returned HTTP 403 on every download until it was upgraded. Neither is something you want happening in front of an audience.

Prefetching removes all of it, and the hook already exists: plan_mix(track_ids=...) restricts the pool to an explicit list, so the planner can only ever choose tracks you already hold.

But rendering is still slow. With every track local and every segmentation cached, a 15.6-minute mix took 192 s of compute. Prefetching does not touch that.

What to actually do

Prefetch a verified pool to S3

Two or three hundred tracks across the genres you will demo, plus the segment JSON cache. Removes the six minutes, the 403 risk and the replan entirely.

Cache the stretched audio

The stretch depends only on the track and the target BPM. Pre-stretch each track at a few canonical tempos and 80% of the per-track cost disappears.

Parallelise track preparation

The six tracks are prepared independently and in series. On a multi-core box that phase drops from 141 s to roughly the cost of one track.

Or pre-render for a truly instant demo

Honest trade-off: a canned mix per prompt shows the output but not the system. Good for a first impression, weak if anyone asks to change the prompt.
